# Experiments

Generative-AI experiments generated by the agent live in `experiments/<name>/`.
Each experiment calls the configured gateway through the **gateway_client SDK**
(`wotan.gateway_client`) - never a vendor's public API - reusing the provider
YAML and the same TokenManager (refresh, retry, 401 handling).

## Layout

- `templates/` - starting scaffolds the agent copies:
  - `webapp/` - FastAPI + HTML/JS page with upload, gateway call, result display
  - `batch/` - process a folder of files into CSV/Excel
  - `notebook/` - Jupyter notebook scaffold
- `entity_extraction/` - working example: extract entities from text/PDF files
  into `output/results.csv`. Tested against the mock gateway (`wotan mock`).

## Conventions (every experiment)

- `README.md` (what it does, how to run), `requirements.txt`, `.env.example`
- Logging to stdout + `output/run.log`; errors reported, never swallowed
- The agent must **actually test** the experiment (against the mock when the
  real gateway is unreachable) before claiming it is done, and say clearly
  which one was used.

## Running

```bash
wotan mock                       # optional: fictional gateway on :8787
cd experiments/entity_extraction
python run.py --input input      # writes output/results.csv
python webapp.py --port 8899     # web UI variant (also started from the Experiments panel)
```

The IDE's Experiments panel starts `webapp.py` (or `run.py`) with `--port` and
proxies the preview under `/preview/<name>/`.
